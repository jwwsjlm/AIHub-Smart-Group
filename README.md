# AIHub 智能分组

一个用于 AIHub 的 Tampermonkey 油猴脚本。它会读取供应商监控数据，按价格、可配置的 TTFT 指标和可用率推荐分组，并可把已有 API 密钥切换到推荐分组。

脚本不会显示或保存完整 API Key。面板顶部会显示当前账户余额；自动检测最多每 60 秒重新读取一次，手动检测会强制刷新。

## 支持页面

| 页面 | 功能 |
| --- | --- |
| `https://aihub.top/*` | 登录后在所有页面显示智能分组面板或右下角 `AI` 按钮 |
| `https://aihub.top/providers` | 读取供应商监控、推荐分组，并按设置自动选择新版大厅的排序和时间维度 |
| `https://aihub.top/keys` | 选择密钥、手动切换，并在原生分组下拉框显示监控状态与所选 TTFT 指标 |
| `https://aihub.top/usage` | 显示分组倍率，并按历史倍率与模型价格复算按量费用、标记异常 |

脚本只在 AIHub 登录状态下启用，不会在其他网站运行。通过侧边栏切换页面时不需要手动刷新。

## 安装

### 方法一：Greasy Fork 安装（推荐）

1. 在浏览器中安装 [Tampermonkey](https://www.tampermonkey.net/) 扩展。
2. 打开 [AIHub Smart Group 的 Greasy Fork 页面](https://greasyfork.org/zh-CN/scripts/587603-aihub-smart-group)。
3. 点击绿色的“安装此脚本”按钮。
4. 浏览器会跳转到 Tampermonkey 安装页面，再点击一次“安装”。
5. 登录 [AIHub](https://aihub.top/)，打开“供应商大厅”“API 密钥”或“使用记录”页面即可使用。

以后发布新版本时，Tampermonkey 会定期检查更新。也可以打开 Tampermonkey 管理面板，在“已安装脚本”中手动检查更新。

### 方法二：GitHub 直接安装

1. 先安装 [Tampermonkey](https://www.tampermonkey.net/) 扩展。
2. 打开 [脚本直装地址](https://raw.githubusercontent.com/jwwsjlm/AIHub-Smart-Group/main/aihub-smart-group.user.js)。
3. Tampermonkey 会自动识别脚本并显示安装页面，点击“安装”。
4. 登录 [AIHub](https://aihub.top/) 并刷新目标页面。

如果打开直装地址后只看到代码，没有出现安装页面，请确认 Tampermonkey 已启用，然后重新打开该地址。

### 方法三：手动安装

1. 点击 Tampermonkey 图标，选择“添加新脚本”。
2. 打开仓库中的 [aihub-smart-group.user.js](./aihub-smart-group.user.js)，复制全部代码。
3. 删除编辑器内原有示例代码，粘贴脚本代码并按 `Ctrl+S` 保存。
4. 确认脚本状态为“已启用”，然后刷新 AIHub 页面。

### 安装后没有显示

- 确认 Tampermonkey 和“AIHub 智能分组”脚本都已启用。
- 确认当前域名是 `https://aihub.top/`。
- 更新或重新安装脚本后，刷新 AIHub 页面。
- 登录后，智能推荐面板或右下角 `AI` 按钮会在所有 AIHub 页面显示；“使用记录”页面还会显示分组倍率和费用核验汇总。

## 第一次使用

1. 打开 `https://aihub.top/keys`。
2. 选择价格、平衡或速度模式。
3. 在“目标密钥”中选择要管理的密钥。
4. 点击“检测”。
5. 等推荐连续通过检测后，点击“切换到推荐分组”并确认。

目标密钥选项会依次显示密钥名、当前分组、倍率和当前设置选中的 TTFT 指标，例如：`main · A001-K12 · ×0.05 · 首 Token 1141 ms`。新版 AIHub 还会在有数据时追加模型检测状态和缓存命中率；选中后，下方详情区会额外显示模型检测原因摘要、所选 Sol/Terra/Luna 的每百万 Token 价格。使用真实用户平均 TTFT 时会同时显示有效用户样本数。如果当前分组没有对应监控数据，会明确显示“暂无数据”。脚本不会显示或保存完整 API Key。

在 API 密钥列表中打开网站原生的“选择分组”下拉框时，每个分组会在同一行显示名称、供应商大厅最新状态、倍率和所选 TTFT 指标。兼容新版挂载到 `body` 的 Portal 下拉和 `role="option"` 选项结构。新版模型检测为“证据不足”“检测失败”“疑似”或“未检测”时会沿用监控警告色并参与“排除监控警告”筛选；检测通过会显示“检测通过”，异常状态可悬停查看完整原因。分组图标、名称和状态文字使用相同状态色：可用为绿色，有监控警告为橙色，不可用为红色，已停用为灰色；暂无监控时只显示文字提示，不改变网站原有的分组样式。TTFT 数值使用绿色加粗显示，长分组名会自动省略，倍率和速率保持可见。没有延迟数据时会显示“暂无数据”。这些信息只用于提示，不会禁用分组、改变排序或影响原有搜索和选择操作；弹层打开期间最多每 60 秒刷新一次。

自动切换默认关闭。打开前会弹出确认；打开后，只有推荐稳定、监控数据未过期、目标密钥不在推荐分组且冷却时间结束时才会切换。手动或自动切换真正执行前还会基于最新行数据和当前设置重新分析，确认旧目标仍符合筛选条件、仍是第一名并与稳定推荐一致；任一条件变化都会取消本次切换并要求重新检测。

## 三种模式

| 模式 | 选择规则 | 适合场景 |
| --- | --- | --- |
| 价格 | 按设置的标称倍率、1 小时真实输入价或 1 小时预测倍率选择最低的可用分组 | 预算优先 |
| 平衡 | 在设置的最高倍率以内，选择当前 TTFT 指标最快的分组 | 兼顾价格和速度 |
| 速度 | 选择当前 TTFT 指标最快的可靠分组 | 响应速度优先 |

## TTFT 采集指标

设置中的“TTFT 采集”可选择推荐、密钥详情和分组下拉所使用的延迟来源：

- **主动探测首 Token**：默认选项，使用供应商大厅主动探测得到的首 Token 延迟。
- **真实用户平均 TTFT**：默认使用 AIHub 当前供应商大厅 `user_avg_ttft_ms` 汇总指标，即真实请求的平均首 Token 时间，并在推荐、候选、密钥详情和分组下拉中显示有效样本数。可设置“最低有效样本数”（默认 `1`）；低于该门槛时会改用主动探测值，并明确显示“样本不足 n/阈值，回退探测”。没有主动探测值时会保留样本不足原因而显示“暂无数据”。`0 ms（未产生数据）`不会被当成有效延迟。

选择真实用户指标后，还可以把推荐速度窗口设为“AIHub 页面汇总”（默认）、近 10 分钟、近 1 小时或近 6 小时。时间窗口使用监控序列中的 `sample_count` 对平均 TTFT 加权，忽略过期、无数据、零样本和无效 TTFT 记录。推荐、目标密钥详情和 `/keys` 原生“选择分组”下拉会统一使用这个窗口。窗口内没有有效样本时会明确显示“近 10 分钟无有效样本，回退探测”等原因；窗口样本低于门槛时会显示“近 10 分钟样本不足 n/阈值，回退探测”。

该选项会影响速度模式、平衡模式以及价格相同时的延迟比较，不改变倍率和最近 10 分钟可用性筛选。

## 价格模式的推荐依据

设置中的“价格模式”可以选择：

- **标称倍率**：默认选项，保持旧版推荐和自动切换逻辑。
- **1 小时真实输入价**：按 `runtime_cache_1h` 已就绪且未过期时的实际输入成本排序。
- **1 小时预测倍率**：仅在后端明确标记预测倍率已就绪且运行期数据未过期时参与排序。

后两种依据不会对单个分组或全局静默回退到标称倍率，避免把不同口径混在同一排序中。面板会显示因未就绪、已过期或缺失数据而排除的数量。该设置仅影响价格模式；平衡模式的上限、速度模式、分组匹配和使用记录费用核验仍使用标称倍率。

## 新版供应商监控字段

脚本兼容供应商大厅新版 `model_health`、`model_detection`、`model_prices`、`cache_hit_rate`、`runtime_cache_1h`、`effective_input_price_per_million_1h`、`effective_multiplier`、`output_tps`、`sla`、`public_detail` 和 `hewei_check_url` 字段：

- `model_detection.status` 兼容 `passed`、`insufficient_evidence`、`detection_failed`、`suspected`、`not_tested` 等新版状态。除通过和明确不适用外，所有显式检测状态都会归入监控警告；默认“排除监控警告”会避免把失败、疑似、未检测或未来新增的未知状态线路作为推荐。
- `model_detection.status` 为 `passed` 时在推荐卡片、目标密钥和原生分组下拉中显示“检测通过”。
- `model_detection.expires_at` 会用于校验检测有效期；已经过期的“通过”结果会显示“检测已过期”并按监控警告处理。新版 `execution_complete`、`all_targets_passed`、`required_targets` 和 `passed_targets` 若明确表明执行或目标未完成，即使状态错误地标成 `passed` 也会显示“检测未完成”。旧接口未返回这些新字段时仍保持原行为。
- `model_detection.reason_codes` 与 `reasonCodes` 会合并去重并转换为可读原因。推荐、候选和目标密钥详情最多内联显示两个告警原因，悬停可查看完整原因；纯通过信息不会挤占内联告警摘要，未知的新原因代码也会安全降级为可读文本。
- `model_health` 会分别汇总 Sol、Terra、Luna 的健康、证据不足、失败和未知数量，避免把 `insufficient` 错误显示为“健康 0/3”；单个模型失败只作为提示，不会直接隐藏整个供应商。
- `model_prices` 会按设置显示 Sol、Terra 或 Luna 的输入、缓存输入和输出价格，单位为美元 / 每 1M Token。价格仅用于展示和费用核验，不改变推荐、排序或自动切换目标。
- `cache_hit_rate` 支持新版百分比字符串（例如 `65.50%`），在推荐、候选和密钥详情中显示缓存命中率。
- `runtime_cache_1h` 会规范化最近 1 小时的用量、Token、缓存成本、刷新时间和就绪状态；顶层缓存命中率缺失时，仅在运行期数据已就绪且未过期时使用其中的精确命中率降级展示。
- 后端明确标记 `effective_multiplier_ready` 且运行期数据未过期时，推荐卡片、候选和密钥详情会显示最近 1 小时真实输入价格与预测倍率；样本不足、数据未就绪或已过期时只在密钥详情解释原因。标称倍率仍是默认推荐依据；显式选择真实输入价或预测倍率时，仅价格模式使用新口径。
- `output_tps` 会在有有效数据时显示输出 Token 速度。WebSocket 支持与订阅类型也会被规范化保留，便于后续页面功能继续适配。
- `sla` 会按 0–1 比例（也兼容百分比数值或字符串）规范化为历史 SLA 百分比，并在推荐卡片、候选列表和当前密钥详情中显示；缺失或超出范围时显示暂无数据，不参与推荐排序。
- `public_detail` 会作为供应商公告显示在推荐卡片、候选提示和当前密钥详情中；`hewei_check_url` 仅接受 HTTP(S) 地址，并以新标签页安全打开禾维检测报告。公告只用于提示，不会自动排除分组。

缺失这些字段时保持旧版行为，不会因为接口未返回新版数据而排除分组。

供应商大厅的定时自动刷新会点击页面原生“刷新”按钮，并兼容新版 `monitor-icon-button` 图标入口与旧版文字按钮。新版页面会优先按按钮语义直接定位，避免每次到期遍历大厅内全部按钮；正常计时保持 1 秒调度精度，按钮尚未渲染或暂时禁用时改为每 5 秒重试。刷新期间只监听新版页面的刷新状态区（按钮和“更新时间”），不再订阅供应商卡片与图表产生的大量 DOM 变更；旧版布局无法定位状态区时会只监听刷新按钮。连续完成信号仍按 50ms 合并检查。点击后仍以页面“更新时间”或供应商数据签名确实变化作为成功依据；即使新版“更新时间”文本粒度较粗、一次刷新内没有改变，也会回退比较供应商数据；当前决策表的 `.decision-row.ledger-row` 也纳入回退签名。仅有刷新按钮结束加载但数据未变化不会被误记为成功，15 秒内没有完成信号会先做最终核验；无变化最多短重试 1 次，随后回到设置的正常间隔，避免后端快照长时间不变时形成高频请求。

## 使用记录费用核验

`/usage` 的完整使用明细会显示费用校验汇总。脚本会复用当前页面已经发起的使用记录查询条件，读取同页接口中的精确 Token、实际费用、历史倍率和计费模式；再根据分组名、历史倍率和模型型号（Sol、Terra 或 Luna），使用供应商接口返回的输入、输出与缓存输入单价复算预计费用。接口不可用或当前行未匹配时，才回退到页面显示值。精确明细按查询条件和当前可见记录缓存，分页、筛选或刷新产生新记录时立即更新，同一视图的五分钟价格刷新不会重复拉取整页明细。缓存仅保留费用核验所需的最小投影字段，不保留或展示完整 API Key、IP、User-Agent 等隐私字段；失败请求只短暂退避，不会作为成功结果长期缓存。新版桌面表格兼容中文、英文、常见列名别称，以及 `data-column`、`data-key`、`data-testid`、`aria-label` 语义列标识；同一次渲染每张表只解析一次表头。即使在“列设置”中隐藏非必要列或调整列顺序，只要保留 API 密钥、模型、分组、计费模式、Token、费用和时间列，费用核验仍会生效。新版小屏页面改用 `data-field` 卡片时，脚本也会识别同一组字段、显示倍率和费用核验；精确接口记录仅在卡片数量与接口投影数量完全一致时按原始顺序匹配，数量不一致则安全回退页面值，避免错配账单。

- 默认仅在费用超出容差时，在原生费用下方追加“预计费用”和偏高/偏低比例；设置为“显示全部”后，正常记录也会显示“一致”。
- 默认相对容差为 `1%`，同时保留 `$0.000005` 的绝对误差下限；精确接口记录不会引入 Token 显示舍入误差。仅在回退读取 `2.6K`、`181.6K`、`2.6M` 等压缩页面 Token 时，才把显示精度可能产生的舍入区间折算为额外费用容差，避免大数值只读误报。
- 价格必须同时匹配规范化分组名和页面记录中的历史倍率。若供应商后来修改倍率，脚本不会用当前倍率回退计算旧记录，避免误报。
- 非按量、未知模型、Token 结构异常、金额缺失或找不到对应历史倍率价格的记录会计入“跳过”，不会被标记为异常。缓存创建 Token/费用目前没有独立可靠单价，包含该费用的记录也会跳过，避免使用缓存读取单价误算。

费用核验是只读提示，不会修改账单、密钥、分组或自动切换行为，也不会读取或展示完整 API Key 与 IP。

## 供应商大厅偏好与自动刷新

设置中的“供应商大厅”可以选择每次打开页面后自动使用的排序方式：

- **倍率优先（从低到高）**：默认选项，自动点击大厅顶部的“倍率”，低倍率线路排在前面。
- **真实价格优先**：自动点击 AIHub 新增的“真实价格”，按页面当前计算出的实际价格排序。
- **用户速度排序**：自动点击“用户速度”，按真实用户速度排序。
- **缓存命中优先**：自动点击“缓存命中”，优先展示缓存命中率更高的线路。
- **成功率优先**：自动点击新版“成功率”（兼容旧版“可用率”），优先展示近期成功率更高的线路。
- **自定义排序**：自动点击“自定义”，并恢复插件中保存的倍率、用户速度、缓存命中率和成功率四项权重。
- **默认排序**：保留 AIHub 自带的默认顺序。

选择“自定义排序”后，设置中会显示四项权重，范围均为 `0–100`。脚本打开大厅时会先选择原生“自定义”，再把保存值写入新版页面的四个原生滑块并触发页面自己的排序更新；AIHub 仍按总权重自动归一化。四项全部填写为 `0` 时会恢复为各 `25`，应用完成后自动收起原生权重面板。控件暂时未渲染时只做有限次数的短暂复查，不会留下长期高频轮询。

“大厅时间维度”可选择跟随网站默认，或固定为 `6h`、`24h`、`7d`、`30d`。保存后会点击新版大厅原生的时间维度按钮；如果新版页面先渲染排序按钮、稍后才挂载时间维度控件，脚本会约每 250ms 轻量复查并在控件出现后自动应用，同时不阻塞自动排序。最多等待 5 秒，旧版页面没有该控件时会自动结束等待并安全跳过，不会留下长期轮询。该选项只改变大厅原生图表的展示范围，不改变智能推荐使用的最近 10 分钟可靠性窗口。

保存设置后会立即应用一次，并纠正目标列当前相反的升降序：倍率、真实价格和用户速度使用升序，缓存命中、成功率、自定义及默认排序使用降序。新版兼容原生 `最优 → 最差 → 默认` 的三段切换：目标排序已经处于反向时会经过默认状态继续收敛，不会提前误判完成。同时兼容中文与英文排序按钮，以及新版 `data-testid`、`data-sort-key`、`aria-pressed`、`aria-selected`、`data-state` 和升降序属性；匹配限定在页面顶部排序区域，不会误点“真实价格/预测倍率”等表头。排序控件已渲染时只观察该控件区域，并过滤无关属性变化；尚未渲染时才临时回退观察供应商监控面板，减少大厅卡片和图表更新带来的 MutationObserver 回调。大厅偏好只在首次打开供应商大厅、确实修改相关选项或同一路由下大厅组件被 SPA 重新挂载时执行；后两种情况会重新应用已保存的偏好，不会因同一组件内的手动调整而反复覆盖。公开供应商大厅在未登录时也能使用自动排序、时间维度和定时刷新。

“定时自动刷新”默认开启，默认间隔为 `60` 秒，可设置为 `15–3600` 秒。刷新时脚本点击 AIHub 页面自带的“刷新”按钮，只重新获取供应商数据，不会整页重载、清空面板状态或改变当前手动选择的排序。页面原生刷新仍可随时手动点击；关闭该选项后脚本不会定时触发。

新版供应商概览接口只有明确返回 `404/410` 时才尝试旧接口；超时或 `5xx` 会直接保留原错误，避免一次故障产生两次无效请求。

监控过期保护只使用实际主动探测点，不再让新生成但无真实数据的用户 TTFT 空桶刷新安全时间；真实用户序列归一化时会删除 `has_data=false`、零样本或零延迟桶。当前新版 6 小时接口的大量空桶不会进入缓存和窗口聚合，旧接口只提供正延迟但没有样本数时按单个样本兼容。

脚本会复用同一时刻发起的供应商数据请求，避免智能面板、密钥下拉和使用记录重复调用接口。体积较大的 6 小时监控序列独立缓存 60 秒，普通 30 秒轮询不会重复下载同一份序列；手动“检测”仍会强制获取最新数据。`/keys` 原生分组下拉只在选择“真实用户平均 TTFT”且窗口不是“AIHub 页面汇总”时按需读取这份序列；默认主动探测和页面汇总路径不会因此增加序列请求或窗口聚合分配。主动探测序列只保存推荐实际读取的 `[时间戳, 0/1 状态]`，并在归一化后仅保留最近 10 分钟窗口；窗口已经过期时仅保留全局最新的一个旧点用于准确判断监控过期，不再缓存其余未参与推荐的 6 小时探测历史。真实用户 TTFT 序列仍保留所选速度窗口需要的有效桶，并压缩为 `[时间戳, 平均 TTFT, 样本数]`，直接用于近 10 分钟、近 1 小时和近 6 小时的加权速度计算；不再缓存每个探测点的未使用延迟、错误文本或重复对象键。已经是紧凑格式的序列会直接复用，不会在合并时再次复制。接口响应归一化后只保留业务使用的规范化行、序列索引和元数据，不再同时缓存原始 `items` 容器及其完整副本；每个供应商行也采用显式字段投影，不再保留 `code`、`rate_multiplier`、原始延迟字段等已经转换过的别名或其他未使用字段。序列接口失败时会使用供应商概览自带的历史桶继续检测，并按 `sample_count` 计权：`operational` 计为成功，`failed` 与混合状态 `degraded` 保守计为失败，`unknown` 不参与计算。概览历史的每个有效时间桶统一保存为 `[时间戳, 0/1 可用状态, 样本权重]` 三元组，权重在归一化时封顶，不再重复保存对象键、未参与推荐的历史延迟字段或按样本数展开大量重复数组；生成推荐行时也会移除已经合并进监控序列的 `history`，避免同一历史数据同时驻留两份。概览桶与完整序列可能用相差数分钟的时间戳表示同一轮监控；合并时会把 3 分钟内的概览点视为重叠并以完整序列为准，避免重复放大最近 10 分钟的样本数或扭曲可用率，只有完整序列确实缺失的概览点才会补入。序列恢复后自动回到完整数据。历史点比概览生成时间晚几秒时会纳入窗口，同时会拒绝明显超前的异常时间。页面切到后台时暂停周期请求和供应商自动刷新，重新回到页面后只在到期时补一次检测。面板最小化且自动切换关闭时也会暂停完整检测轮询，展开后按需补刷；展开状态的监控年龄与冷却倒计时改用自适应单次定时器，仅在显示文字或过期状态即将变化时唤醒，稳定阶段不再固定每秒执行 DOM 更新。自动切换开启时仍会保持检测。SPA 的 `pushState`、`replaceState`、前进后退和哈希变化会即时触发功能切换，常驻路由复查从每 2 秒降为每 10 秒一次，仅用于兼容页面静默替换根节点的情况；重复注入会复用并在最后一个实例退出时释放 History 补丁。原生下拉和使用记录的 DOM 更新采用目标区域观察与短延迟合并；使用记录主区域只监听表格或卡片挂载等结构变化，文字变化仅在识别出的明细表格和移动卡片列表内监听，统计图表和概览文字刷新不会触发费用核验重渲染。SPA 重新挂载使用记录主区域时会自动清理旧明细监听并切换到新节点，重复注入脚本也会先销毁旧实例，避免叠加定时器和监听器。

`/keys` 原生分组下拉的监控刷新采用菜单挂载事件驱动：下拉未打开时不再每分钟扫描整页，打开后才建立一次性刷新计时，关闭、切到后台或离开页面时立即释放。`/usage` 的供应商倍率与价格刷新也按上一次请求完成时间精确安排下一次 5 分钟刷新，避免固定 interval 因请求耗时错过一个周期；页面进入后台后不会保留刷新定时器。供应商排序控件如果加载较慢，会先由 DOM 观察器即时捕获，再以 5、10、20、40、60 秒指数退避兜底，不再永久每 5 秒扫描；后台暂停，回到前台立即恢复控件检测。

### 平衡模式如何工作

平衡模式使用一个直接的倍率上限：

1. 先按当前可靠性设置过滤分组，例如当前状态、最近 10 分钟可用率和监控警告。
2. 排除倍率高于“允许切换的最高倍率”的分组。
3. 在剩余分组中选择当前 TTFT 采集指标最快的一个。

默认最高倍率为 `0.1`。例如设置为 `0.1`：

- `×0.04`、`×0.08` 和 `×0.1` 可以参与比较。
- `×0.11` 和 `×0.2` 会被直接忽略。
- 如果没有分组满足上限和可靠性条件，平衡模式不会推荐或自动切换。

设置方法：

1. 打开右下角智能分组面板。
2. 将“模式”选择为“平衡”。
3. 展开“设置”。
4. 在“允许切换的最高倍率”中填写数字，例如 `0.1`。
5. 点击“保存设置”，等待重新检测。

输入倍率时，设置下方会实时显示符合上限的分组数量，例如：`只考虑倍率 ≤ ×0.1 · 6 个分组可选 · 将选主动探测首 Token 最快`。输入阶段仅用于预览，出现“未保存”时不会改变推荐或自动切换目标；点击“保存设置”后才会正式生效。

保存后，平衡模式推荐卡片会显示当前采集来源，例如：`倍率上限 ×0.1 · 范围内主动探测首 Token 最快`。

最高倍率是固定的绝对上限，不会随当前最低倍率变化，也不会绕过可用性和警告过滤。它会同时限制推荐卡片、手动切换和自动切换目标。

## 设置与保存

桌面端面板使用左右双栏：左侧用于检测、推荐和密钥切换，右侧通过“设置 / 日志”标签切换内容。两栏分别滚动，面板不会因为打开设置或查看大量日志而超出屏幕顶部。脚本会记住最后打开的“设置”或“日志”标签。窄屏设备会自动改为纵向单列，主内容和设置/日志按实际内容高度依次排列，并在面板内部统一滚动，避免设置或日志遮挡上方操作区。候选分组列表仍保持独立滚动，避免内容过长把设置区推到很下方。

设置区域按“可靠性筛选”“TTFT 采集”“价格模式”“模型价格”“用量费用核验”“供应商大厅”“检测与切换”“平衡策略”分区，可以调整：

- 最近 10 分钟最低可用率（可自行修改，`0.1` 表示 `10%`）
- 可用性判断方式：按百分比、按成功监控点数或按连续成功点数
- 连续通过次数
- 最低历史 SLA（默认 `0`，关闭筛选；设置大于 `0` 后缺失或低于阈值的供应商不会参与推荐和切换）
- 最低输出速度（单位 `tok/s`，默认 `0`，关闭筛选；启用后无输出速度数据或低于阈值的供应商不会参与推荐和切换）
- 检测间隔
- 自动切换冷却时间
- 平衡模式允许切换的最高倍率
- 排除分组关键词
- 是否排除监控警告
- 推荐和展示使用主动探测还是真实用户平均 TTFT
- 真实用户平均 TTFT 使用页面汇总、近 10 分钟、近 1 小时或近 6 小时窗口
- 真实用户平均 TTFT 参与推荐前的最低有效样本数
- 价格模式使用标称倍率、1 小时真实输入价或 1 小时预测倍率
- 推荐、候选和密钥详情显示 Sol、Terra、Luna 哪个模型的价格，或关闭价格展示
- 是否核验使用记录费用、仅显示异常或显示全部，以及相对容差
- 供应商大厅打开后自动使用默认、倍率、真实价格、用户速度、缓存命中、成功率或自定义排序；自定义模式可保存四项权重
- 供应商大厅打开后自动跟随网站默认时间维度，或固定使用 6 小时、24 小时、7 天、30 天
- 是否定时刷新供应商大厅，以及刷新间隔
- 是否开启自动切换

点击“保存设置”后，配置会写入当前浏览器的 Tampermonkey 存储。模式、目标密钥和最近一次切换记录也会保存。编辑单个设置时只更新受它影响的预览，调整供应商刷新间隔等无关字段不会重复扫描候选分组。

面板顶部会显示当前账户余额。自动检测会复用 60 秒内的余额结果，手动点击“检测”会强制读取最新余额；余额不会写入日志或配置。

“排除分组关键词”使用 `|` 分隔多个关键词，例如 `free|unstable`。匹配忽略大小写，只要分组名称包含其中任一关键词，该分组就不会参与价格、平衡或速度模式的推荐和切换。输入时会实时显示命中的分组数量和部分名称，保存后才正式生效。

可用性判断默认使用最近 10 分钟可用率。由于 AIHub 监控通常每 5 分钟产生一个点，也可以切换为“成功监控点数”或“连续成功点数”：前者表示窗口内累计成功多少个点，后者表示最近的连续成功点数。例如设置为 `2`，前者允许前后两个点成功，后者要求最近两个点都连续成功。

切换冷却支持小数，例如 `0.1` 分钟表示 6 秒。设置下方会显示分钟换算结果；冷却期间还会实时显示剩余时间。

## 默认推荐规则

- 当前监测状态必须可用。
- 最近 10 分钟必须有有效探测样本，可用率至少 `10%`。
- 10 分钟可用率阈值可在设置中自行修改。
- 默认排除带监控警告的分组，包括新版模型检测“证据不足”和“检测失败”。
- 推荐连续通过默认 `2` 次检测后才视为稳定。
- 自动切换默认关闭，默认冷却时间为 `10` 分钟。
- AIHub 监控样本通常约每 5 分钟更新一次。脚本以序列中的最新实际样本为准，固定超过 `600` 秒（10 分钟）未更新才视为过期；这个保护值不开放手动调整。过期时推荐卡片会变红并写入一条错误日志，恢复后会写入一条恢复日志；推荐仍会显示，但手动和自动切换都会暂停。

脚本通过 AIHub 的分钟级监控序列计算最近 10 分钟可用率。价格模式按当前选择的价格依据升序排列；价格相同时依次比较最近 10 分钟可用率、当前 TTFT 指标和标称倍率。真实用户平均 TTFT 样本不足时会使用主动探测参与比较，避免少量真实请求直接改变推荐或自动切换目标。6h、24h 等长期历史不会阻止近期可用的分组进入推荐。推荐卡片会显示监控数据年龄、实际参与比较数量，以及关键词、不可用、可用率不足、监控警告、SLA 无数据、SLA 不足、输出速度无数据、输出速度不足、真实用户样本不足回退和价格数据不可用分别排除了或影响了多少分组；模型检测异常只统计实际进入监控警告筛选阶段的线路。

供应商监控数据在面板展开或自动切换开启时按设置的检测间隔刷新。密钥列表会在首次加载、手动检测和缓存超过 5 分钟时重新读取；密钥接口短暂失败时会保留已经读取的列表，避免目标密钥突然消失。

## 使用日志

面板中的“使用日志”会记录：

- 首次检测、手动检测及推荐结果变化
- 密钥读取或监控检测失败，以及恢复状态
- 模式或设置变化
- 自动切换开关变化
- 手动或自动切换结果
- 自动切换跳过原因（状态变化时记录一次）
- 请求失败和切换失败

最多保存最近 100 条，可以随时清空。日志只保存时间、动作、分组名和错误摘要，不保存完整 API Key、登录令牌或请求正文。

## 切换与安全

- 手动切换前会弹出确认框。
- 自动切换只修改已选密钥的分组，不创建新密钥。
- 登录令牌只从当前 AIHub 页面临时读取，用于当前请求。
- 完整 API Key 和登录令牌不会写入日志或脚本存储。

## 常见问题

### 面板没有出现

确认已登录 `aihub.top`，并在 Tampermonkey 中启用了脚本。更新脚本后刷新页面；如果旧面板仍在，检查是否重复安装了旧脚本。

### 显示“未找到页面登录令牌”

请在保存登录状态的同一个 Chrome 配置中重新登录 AIHub，然后刷新 `/keys` 页面。

### 显示“密钥接口返回 401”

当前登录已经失效。重新登录后点击“检测”。

### 没有推荐分组

检查“最近 10 分钟最低可用率”和“排除监控警告”设置。可用率输入范围是 `0–1`，例如 `0.1` 表示 `10%`、`0.9` 表示 `90%`。最近 10 分钟没有有效探测样本的分组不会参与推荐。也可以展开使用日志查看检测结果或错误摘要。

### 切换按钮是灰色

常见原因包括：尚未选择目标密钥、推荐没有连续通过规定次数、监控数据已经过期、当前密钥已经在推荐分组，或者检测仍在进行。把鼠标移到按钮上可以查看具体原因。
